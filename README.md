# IMWatchingU ❤

Windows 桌面监控工具：选择窗口或屏幕区域，在本地识别文字，命中关键词时向 QQ 好友或群发送通知。也可以单独使用色块变化声音报警。

支持多个监控任务、关键词规则、多个接收对象，以及文字和截图通知。监控区域与发送截图区域可以分别设置。

## 启动应用

如果你拿到的是应用压缩包，解压后运行 `IMWatchingU❤.exe`。请保留同目录中的全部文件，不要单独移动 EXE。

如果你下载的是本仓库源码，在 Windows 上安装 Python 3.12 后，在项目目录打开 PowerShell，执行：

```powershell
py -3.12 -m pip install uv
py -3.12 -m uv sync --frozen
.\.venv\Scripts\python.exe -m screen_qq_ocr
```

之后只需执行最后一行即可启动。首次启动不会自动监控或连接 QQ。

默认使用 Windows OCR，识别语言取决于系统已安装的 OCR 语言支持。QQ 通知需要本机 NapCat Shell 和可登录的 QQ 环境；应用不会自动下载安装 NapCat。当前版本仍有待实机验证的功能，见文末说明。

## 第一次使用

### 1. 选择要监控的画面

1. 打开监控页，选择一个任务；需要同时监控多个画面时，点击「新建任务」。
2. 点击「刷新」，选择窗口或显示器，再点击「使用来源」。
3. 点击「选择监控区域」，在弹出的全屏选区界面中圈定需要识别的范围。
4. 点击「识别一次」，在「最近识别」中检查文字是否正确。此操作不会发送消息。
5. 如果需要附图通知，点击「选择截图区域」，单独设置发送的画面范围。

「重置监控区域」和「重置截图区域」分别恢复为整个来源画面。尽量缩小监控区域，保留清晰文字，以减少无关内容对识别的影响。

### 2. 登录 QQ 并连接消息通道

打开「QQ 连接」：

1. 在「连接与运行」中检查 NapCat 启动文件、配置目录和账号配置。应用包若附带 NapCat，会尝试自动找到；否则选择本机已安装的 Shell 启动文件及其 `config` 目录。
2. 多账号环境下，选择对应的 `onebot11_账号.json`；首次登录没有账号配置时，使用默认配置。
3. 进入「QQ 登录」，点击「启动并显示二维码」，用手机 QQ 扫码，等待登录完成。
4. 检查消息通道状态；必要时回到「连接与运行」，点击「读取配置」和「连接并核验」。

如果已有正在运行的本机 NapCat，也可以直接填写 OneBot 正向 WebSocket 地址与消息通道凭据，然后点击「连接并核验」。管理端凭据与消息通道凭据是两套独立凭据，请勿混用。

### 3. 设置关键词和通知内容

在关键词页新增并启用规则，填写关键词和「目标数量（至少）」。例如，关键词为「完成」、数量为 `2`，表示同一次识别结果中至少出现两次「完成」才算命中。

随后进入发送配置页：

1. 在「发送对象」中勾选需要接收通知的好友或群，可以选择多个对象。
2. 在「消息格式」中选择仅文字、文字与区域截图，或仅区域截图。文字可使用命中行、完整识别文本、固定文本或消息模板。
3. 在「发送条件」中设置连续确认帧数、重复方式、冷却时间和发送前倒计时。
4. 点击「应用发送配置」，再用「使用最近结果试算」或「使用示例试算」检查结果。
5. 核对接收对象后，可点击「测试发送」验证实际收信。试算不会发消息，测试发送会。

默认发送策略供规则共用，也可以在单条关键词规则中覆盖发送条件、格式和对象。「消息别名」用于替换模板中的 `{keyword}`，不改变实际匹配的关键词。

模板可使用 `{keyword}`、`{count}`、`{threshold}`、`{hit_line}`、`{ocr_text}` 和 `{capture_time}`，例如：

```text
检测到 {keyword}，共 {count} 次。
{hit_line}
时间：{capture_time}
```

「目标数量」是单次识别中的出现次数；「连续确认帧数」是连续多少次识别都命中，两者含义不同。

### 4. 开始监控

回到监控页，勾选「关键词检测」，点击「开始监控」。QQ 未登录或消息通道未连接时，应用会提示先完成连接。

可以切换任务查看不同画面，其他任务继续运行。「停止」只停止当前任务，「停止全部」停止所有任务。发送倒计时期间，可点击「取消待发送」。发送结果可在记录页查看。

每次启动后，请检查任务来源与区域，再开始监控。规则和默认发送策略由各任务共用；修改后请停止并重新开始相关关键词监控，使其使用新配置。

## 只使用声音报警

选择来源和监控区域，勾选「色块报警」，取消「关键词检测」，再点击「开始监控」。色块报警不需要 OCR 或 QQ 连接。

声音与冷却时间可在应用设置中调整，也可以试听。点击「保存设置并停止监控」后，需要重新开始监控。

## 导入、备份与退出

- **关键词导入导出**：支持 TXT 和 JSON。完整备份规则与发送策略请选择 JSON；TXT 仅保存关键词、数量和固定正文，格式为 `关键词|数量|固定正文`，每行一条。
- **本地数据**：默认保存在 `%LOCALAPPDATA%\IMWatchingU\`，包含规则数据库、应用设置和日志。备份整个数据目录前请退出应用；连接凭据保存在 Windows Credential Manager 中，不随目录备份迁移。
- **后台运行**：启用「关闭窗口时最小化到托盘」后，关闭窗口仍会继续运行。需要完全退出时，使用托盘菜单退出。
- **NapCat 退出**：退出应用会停止由本应用启动的 NapCat 及其 QQ 子进程。「断开消息连接」只断开消息通道；外部启动的 NapCat 需从其自身入口退出。

截图和 OCR 在本机处理；启用 QQ 通知后，消息文字及所选截图会发送给配置的接收对象。

## 常见问题

**识别不准确或没有文字？** 先用「识别一次」检查，确认区域内文字清晰，并检查 Windows OCR 语言支持。也可以在应用设置中选择本地 Tesseract，需要自行安装 `tesseract.exe` 以及 `chi_sim`、`eng` 语言模型。

**监控暂停或无法选择窗口？** 窗口最小化、关闭、显示器断开，以及锁屏或休眠都会影响采集。同名窗口无法唯一定位时，请先关闭多余窗口或改选显示器。恢复画面后检查任务状态，必要时重新选择来源并开始监控。

**命中了却没收到通知？** 检查规则是否启用、目标数量和连续确认条件是否满足、是否处于冷却期，以及 QQ 连接与接收对象是否有效。在发送配置页试算，再查看记录页中的发送结果。断线重连不会补发历史通知。

**二维码过期或提示账号已登录？** 过期时点击「刷新二维码」；提示重复登录时，先退出使用同一账号的其他 QQ / NapCat 会话，再刷新。应用不会自动关闭外部 QQ 实例。

当前版本尚未完成干净 Windows 环境安装、真实 QQ 扫码及好友/群收发的完整验收，本地 Tesseract 实际识别也待验证。首次使用请先完成单次识别和测试发送，确认当前环境可用。
