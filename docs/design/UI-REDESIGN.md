# UI 重设计方案 · Gray / Amber

日期：2026-09-05。状态：已落实到 PySide6 桌面界面。设计稿保留作参考，实际交互与验收以 [桌面 UI 重构记录](../acceptance/2026-09-05-ui-redesign.md) 为准。

## 设计方向

采用用户确定的“偏灰黑主色、橙色背景光晕、柔和灰白表面”。炭黑导航与主按钮建立视觉骨架，内容卡片保持灰白，低饱和橙光出现在工作区右上角。橙色只辅助选中状态、裁剪框和关键词命中；绿色表示就绪/成功，错误状态保留语义红色。

参考站点为 [本机 NapCat WebUI](http://127.0.0.1:6100/webui/)。实际查看了未登录页面和公开样式：其采用柔和背景光晕、浅灰表面、圆角输入框与按钮反馈。登录后页面需要鉴权，本次没有读取账号凭据或假定已查看后台。参考了公开组件中的短时缩放/渐变机制，具体布局和配色按本项目任务重新设计。

## 页面结构

1. **监控工作台**：顶部仅保留页面标题与 QQ 总状态；任务用可直接选中的卡片呈现名称、来源、运行状态。中央完整来源预览，右侧监控设置与最近识别；底部是最近通知或待发倒计时。主操作“新建任务”，当前任务单独开始/停止；“停止全部”降低视觉权重。
2. **关键词规则**：直接编辑目标数量，数量始终紧邻关键词。规则内容与发送策略摘要分层；新增/编辑以短表单呈现，详细覆盖策略可展开。保留正式版搜索、批量启停、导入预览和删除撤销能力；图稿先展示主要流程。
3. **QQ 与 NapCat**：账号卡片在上；Shell 启动配置与消息通道并排。“启动并连接”为明确主操作，配置路径与 token 降低视觉噪声。过程清晰呈现“读取配置 → 启动 Shell → 等待登录 → 核验通道”。二维码只来自真实管理接口；设计稿用模拟登录代替真实二维码。
4. **发送策略**：发送对象、消息类型和正文为主栏；连续确认、冷却、倒计时为次栏。预览使用独立弹层，测试发送对象和账号需再次明确展示。设计稿只模拟预览，不进行实际发送。
5. **活动记录**：按时间纵向组织，成功、命中、暂停、失败均有文字状态，不单靠颜色。展开单项再展示任务、目标、错误及分项回执。
6. **偏好设置**：外观、动效、资源与识别分组。设计稿额外提供慢放动效演示；该演示控件不放进正式用户流程。

宽度不足时，导航折叠为图标，识别结果移到预览下方；任务卡片换行。窄幅设计稿可堆叠浏览，但正式 Windows 应用无需模拟手机布局。禁止把完整桌面固定缩小成文字不可读的缩略图。

## 动画与交互

统一原则：短距离、自然减速、不等待动画执行业务。普通变化用 `cubic-bezier(.2,.8,.2,1)`；退出用短时 ease-in。只在用户操作或业务状态变化时动，不让背景光晕、边框、状态灯持续循环。

| 场景 | 时长 | 视觉变化 | 行为约束 |
| --- | --- | --- | --- |
| 按钮悬停 | 120 ms | 灰度、边框、浅阴影微变 | 不改变控件占位 |
| 按压/释放 | 80 / 120 ms | 视觉内容缩放到 0.98 后恢复 | 点击立即执行；布局尺寸不缩放 |
| 主按钮反馈 | 240–280 ms | 一次低透明度局部涟漪 | 仅主操作；不扩散到整块面板 |
| 导航切换 | 220 ms | 选中背景过渡；内容上移 8px 并渐显 | 导航和预览外壳稳定；快速切换中断前次动画 |
| 切换监控任务 | 180–220 ms | 当前内容 5px 位移与渐显 | 切换即更新任务身份；真实帧不跨任务混合 |
| 创建任务 | 220 ms | 新项进入、选中；内容区域跟随更新 | 其他任务的状态与列表位置保持可辨识 |
| 弹层打开 | 280 ms | 14px 上移、0.98→1 缩放、透明度渐变 | 背景轻遮罩，首个输入自动聚焦 |
| 弹层关闭 | 150 ms | 7px 下移和渐隐 | Esc 关闭，焦点回到触发按钮；不可穿透点击 |
| 开关切换 | 160–220 ms | 滑块平移与轨道灰度变化 | 保存失败恢复原状态并给出原因 |
| 裁剪拖动/缩放 | 指针实时跟随 | 仅框、控制点和尺寸数字更新 | 拖动过程中无缓动；释放后应用一次，最小 16×16 像素 |
| 单次 OCR 完成 | 180–220 ms | 时间更新、结果轻渐显 | 不对截图纹理做淡入；按钮忙碌时防重复提交 |
| 命中与倒计时 | 220 ms 进入 | 底部通知区短距离进入；每秒更新数字 | 倒计时来自业务时钟；减少动效/慢放都不改变真实秒数 |
| 发送成功 | 180 ms | 状态图标与文案切换 | 只按真实回执显示成功；未知结果不得显示成功动画 |
| 取消待发 | ≤120 ms | 状态立即改为取消 | 后台立即取消，已提交请求按真实结果呈现 |
| NapCat 启动 | 每阶段 160 ms | 对应步骤线与文字更新 | 阶段必须来自实际状态；不伪造百分比或成功 |
| 保存反馈 | 180 ms 进入，150 ms 退出 | 小型状态提示，上移 8px | 成功约 3 秒消失；错误持续可见且可操作 |
| 错误/断开 | 立即状态更新 | 局部错误信息出现 | 不晃动整个窗口、不强闪屏、不自动抹去错误 |

设计稿提供任务切换、独立启停、新建、可拖动/缩放裁剪、数值裁剪、单次识别反馈、倒计时取消、NapCat 分阶段模拟、弹层和主题切换。背景光晕固定。可以在“偏好设置 → 动效演示”慢放交互。

### 减少动态效果与可访问性

- 遵循系统“减少动态效果”，应用内可进一步关闭运动。
- 关闭平移、缩放、涟漪，只保留即时状态更新或不超过 80ms 的局部透明度变化；业务倒计时与任务调度保持原样。
- 弹层支持焦点约束、Esc 和焦点归还。图标按钮有语义标签，焦点轮廓可见；裁剪提供数字输入替代拖动。
- 状态同时有文字与图形，成功绿色不承担唯一语义。关闭、删除、断开等操作需要与主要动作保持明确区分。
- 失焦/最小化时停止装饰动画；保持业务采集、OCR 与通知逻辑按原设置工作。

## PySide6 落实方案

1. 先建立颜色、间距、字号和状态 tokens；主题切换一次更新，保持页面对象和任务选择。
2. 导航、任务列表、预览工具栏与通知条分别做复用组件。避免对整页叠加 QGraphicsOpacityEffect 导致采集画面与文字一起反复闪烁。
3. 使用 QPropertyAnimation / QVariantAnimation / QParallelAnimationGroup 驱动局部视觉属性。Qt 原生布局管理的几何尺寸不参与按压缩放；缩放在绘制层或独立内容容器内完成。
4. 导航和任务切换只动画文本/控件容器。来源身份变更时先清理旧结果，再显示新任务缓存或加载状态；不能用交叉淡化掩盖来自不同任务的画面。
5. 连续状态更新采用“从当前视觉状态继续”，不叠加动画队列。错误、取消、停止立即更新模型，动画是状态展示的结果。
6. 背景光晕可用缓存的 QPainter 径向渐变绘制；静态缓存，不每帧做全窗口模糊。弹层阴影与遮罩使用局部范围，避免显卡占用影响 OCR。
7. 帧更新只触发预览区域 repaint；拖动选区期间不重启采集，释放后提交 ROI。动效不改变 session、规则 revision、队列或冷却逻辑。
8. 保留现有单实例、托盘、锁屏暂停、错误显示和原功能入口；完成页面替换后执行既有 64 项回归及新增关键交互验收。

## 桌面实现说明

统一主题入口为 `ui/appearance.py`，控件与弹层为 `ui/widgets/controls.py`，样式与图标位于 `ui/theme/`。所有页面使用同一套控件状态与配色；Qt 文件选择器关闭原生对话框模式，标题栏、图标、右键菜单与下拉弹层同步主题。

实际动效采用按钮 80–120ms、页面标题 220ms、弹窗 280ms 的 OutCubic 渐变。监控预览和整个页面不做透明度动画，避免影响采集画面刷新；橙色背景光晕保持静止。减少动画关闭这些过渡。最小窗口为 960×640，较长配置页纵向滚动。


### 裁剪预览交互补充

已确认的裁剪区域居中显示，按可视区域的 78% 自适应缩放，最高为全图适配倍率的 8 倍。框内拖动采用固定选框、平移背景的交互，位移按当前倍率反算为源图坐标并限制在图像边界内。绘制和控制点缩放期间保持当前视角，松手后立即更新并重新居中，后台异步校验与采集；每次提交携带递增版本，旧回执不会覆盖新选区或打断正在进行的拖动。失败时按最新回执同步后台实际选区。同任务的后台裁剪操作串行执行，避免监控停止/重启相互干扰。Esc 取消拖动，重置裁剪回到全图；任务切换和预览尺寸变化重新适配视角。同尺寸实时帧更新保留拖动视角。
