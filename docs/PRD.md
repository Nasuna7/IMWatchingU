## 1. 产品目标

将 `legacy/` 中的屏幕识别工具重构为 Windows 原生桌面应用。用户在应用内选择屏幕或窗口、圈定区域、管理关键词，并启动 NapCat、扫码登录 QQ、选择好友或群。监控过程中，本地 OCR 命中规则后通过 NapCat 发送文字及可选截图；独立的色块闪烁模块提供声音报警。

首版技术选定 Python + PySide6 Qt Widgets。这里的“后端”是桌面程序内部的 Python 业务层与工作线程，不设置面向界面的 HTTP 服务。NapCat 是独立的第三方运行时，其内部技术栈不属于需要改写为 Python 的项目业务代码。

成功标准：普通用户无需 Node.js、浏览器、终端和手动修改 JSON，即可完成 NapCat 配置、启动与登录，并在应用内方便地配置“什么情况下发送、发送什么格式、发送给谁”。应用提供默认发送策略、按关键词覆盖、消息预览和测试发送，形成完整配置闭环。截图和 OCR 在本机执行；用户配置的通知内容经 QQ 网络发送，不沿用旧版“所有数据均不上传”的误导性描述。

## 2. 现状与迁移依据

实际阅读范围：`legacy/README.md`、`public/index.html`、`public/app.js`、`server.js`、`ocr-win.ps1`、`qq-send.ps1`、`keywords.txt`。以代码行为为基线；旧文案和代码冲突时在下表明确处理。

| 旧版能力/行为 | 桌面版决策 | 优先级 |
| --- | --- | --- |
| 浏览器选择整屏、窗口、标签页 | 原生选择显示器或窗口；标签页通过其浏览器窗口捕获 | P0 |
| 预览中拖拽裁剪、清除区域 | 保留，并处理多显示器与 DPI 缩放 | P0 |

| 灰度、对比度、小区域放大、暗底反色 | 保留可关闭的 OCR 预处理，截图发送使用原始彩色帧 | P0 |

| 冷却时长为全局配置，但按关键词独立计时 | 保留默认值，并支持规则单独覆盖冷却时长 | P0 |

| Enter/Ctrl+Enter、查找并激活 QQ 窗口、剪贴板粘贴 | 移除，改为按 QQ 账号与目标 ID 调用 NapCat | P0 |
| 发送前倒计时 | 保留，新增可取消、停止监控时取消待发送任务 | P0 |
| 250ms 色块采样、连续变化、3 秒声音 | 保留，独立于 OCR 与 QQ 连接 | P0 |
| `keywords.txt` 持久化 | 兼容导入导出，正式数据存入 SQLite | P0 |
| 页面隐藏暂停监控 | 改为最小化/托盘后继续监控，仅降低预览刷新 | P0 |
| 测试文字、测试截图、单次识别、运行日志 | 保留；单次识别明确不自动发送 | P0 |

实现差异说明：

- 旧版 `consecChanges >= 4` 表示连续 4 次相邻采样变化，需要至少 5 个有效采样点；首版采用这一语义。
- 旧版色块算法遍历颜色像素，没有 OCR 文字框遮罩。“自动排除文字区域”不作为首版已具备能力；后续优化列入 P1。
- 旧版启动监控始终检查 OCR 就绪；新版只启用色块时不要求 OCR 或 QQ，兑现模块独立的产品意图。
- 旧版在发送前写入冷却时间；新版从任务被接纳时开始冷却并占用规则，明确失败与未知结果处理，避免断网重发刷屏。

## 3. 范围与默认决策

### 3.1 P0 发布范围

Windows 10 22H2 / Windows 11 x64；一个活动 QQ 账号、一个采集源、一个识别区域、一组规则。支持一个默认好友或群目标，以及每条关键词规则覆盖为另一个好友或群；每条规则同一时刻只指定一个目标，不做一次命中广播到多个对象。NapCat 可视化配置、发送条件、发送格式和对象配置均为 P0。文字识别支持简体中文和英文。所有上表 P0 功能纳入首版完整验收。

原生登录页显示二维码、登录状态和账号信息；手机 QQ 扫码确认是正常登录步骤。“应用内登录”指桌面内完成二维码展示及状态处理，不要求将完整 QQ 客户端窗口嵌入。

### 3.2 后续功能

P1：多区域任务、文字区域遮罩、OCR 替代引擎、导入完整配置包、可选的无障碍强化。

不在本次首版：多账号并发、群发任务、聊天客户端、消息自动回复、云 OCR、Web 管理页面、移动端、跨平台适配、自动更新 NapCat、任意脚本或正则执行。

Windows 10 的兼容性必须以所冻结的 Qt/Python/NapCat/QQ 组合实测，不承诺任意第三方新版本都支持。版本锁定是发布前任务，不在 PRD 中猜定“最新版”。

## 4. 用户流程

### 4.1 首次启动

1. 显示主窗口和简短引导，检查用户数据目录与配置版本。
2. “QQ 连接”页选择已安装 NapCat 的目录，或选择本地官方 Windows 发行包进行安装准备。界面完成路径校验、解压/启动所需初始化及进度展示；不让用户自行运行终端命令。
3. 在“QQ 连接 → NapCat 配置”中使用“自动配置本机连接”，应用生成管理与消息通道配置；需要时展开高级连接设置。点击“应用并启动”，后台启动受管理进程，检测管理接口可用后，在原生页面展示二维码。
4. 用户用手机 QQ 扫码；应用显示待确认、已登录等实际可观测状态。无法区分的中间状态使用“等待登录”，不虚构已扫码事件。
5. 校验 OneBot 鉴权与在线账号，加载好友/群列表，在“发送配置”页选择默认对象、默认发送条件和消息格式。
6. “监控”页选择显示器或窗口，在预览中圈定区域。
7. “关键词”页新增规则或导入旧文件。每条规则默认继承发送配置，也可在编辑面板覆盖条件、格式或对象；在监控页执行“立即识别一次”查看命中预览。
8. 在“发送配置”页选择规则，用示例或最近识别结果进行本地试算，核对条件判定、最终消息和目标。用户点击“测试发送到所示对象”才实际发送；测试成功后可开始监控，测试不是强制前置条件。

运行时自动下载不作为首版前提；提供官方获取入口和本地导入流程。若发行包初始化需要交互安装器，可以在应用内发起受信任安装器，并展示完成条件；必要系统 UAC 提示不等同于业务界面依赖外部浏览器。

### 4.2 日常监控

启动应用后恢复设置，默认不自动启动监控。用户启动/连接 NapCat，恢复有效会话或重新扫码，核对账号及接收目标，再开始监控。顶部持续显示采集、OCR、QQ、监控四类状态；最小化继续工作；托盘可恢复窗口、停止监控或退出。

### 4.3 仅色块报警

选择采集区域，启用色块监控，关闭关键词监控，即可运行。无需关键词、OCR 模型、NapCat 或 QQ 登录。OCR 失败不停止正常运行的色块分支。

## 5. 功能需求

### F01 桌面生命周期

- 主窗口支持移动、缩放、最大化、最小化、Windows 吸附、键盘导航及系统托盘。
- 默认关闭按钮最小化到托盘，首次给出轻提示；托盘不可用时不得隐藏为无法找回的后台进程。设置中可改为直接退出。
- 同一用户数据目录只允许一个实例，第二次启动激活已有窗口。
- 显式退出依次停止接纳任务、取消待发送、停止采集与声音、关闭工作器，再停止本应用启动的 NapCat 进程树。附加到已有实例时只断开连接。
- NapCat 崩溃时不导致主界面退出。不得通过进程名批量结束用户其他 QQ 实例。

### F02 捕获与区域

- 显示器列表展示名称、分辨率与主屏标识；窗口列表展示标题、所属程序，过滤本应用和无效窗口。
- 默认全采集源；支持拖拽选择、重选、清除裁剪。最小区域 16×16 物理像素；拖拽反方向与越界应正常归一化。
- 记录显示器/窗口标识与相对区域；重启后先验证源，不按旧坐标直接开始监控。
- 窗口移动时区域随窗口内容移动；窗口关闭、最小化、采集失败或显示器断开时暂停该源，取消未发任务并提示重新选择。
- 显示器模式捕获实际可见桌面；窗口模式优先使用 Windows Graphics Capture，遮挡窗口的效果须通过实测。不可捕获的受保护内容、失效窗口和黑帧不得作为正常画面反复触发。
- 原生捕获与 DPI 映射必须覆盖 100%、125%、150%、200% 缩放及副屏负坐标；不支持跨显示器拼接裁剪，用户选择单一显示器。
- 标准预览上限 15fps；低资源模式 8fps、预览最长尺寸限制到 1280×720 包围框内。原始 ROI 捕获不因预览缩小而强制降质。
- 截图默认只在内存中，预览与发送图片不得使用灰度/反色后的 OCR 输入。

### F03 OCR

- 首版提供 Windows OCR 与本地 Tesseract，默认 Windows OCR；缺少中文识别组件时说明原因并提供 Tesseract 切换入口，不静默更换引擎。
- Python 调用 WinRT；Tesseract 由 Python 适配器调用本地引擎，可作为附带可执行组件运行。业务逻辑不继续依赖 PowerShell OCR 脚本。
- 调度间隔选项 2/3/5/10 秒，默认 3 秒。定义为任务结束到下一次启动的等待时间，避免与旧版周期语义不一致。
- 同时最多一个 OCR 任务；不排队积累过时帧。展示最近结果、非空行数、非空白字符数、引擎、耗时、采集时间。
- 输入最大边档位 1280/1920/2560，默认 1920；先裁剪，再按边长上限缩放。小区域可放大至 2 倍，但不得超过引擎能力上限。
- 预处理默认开启：灰度、对比度拉伸、暗底反色；支持关闭以进行对比。Windows OCR 默认使用彩色输入，Tesseract 默认使用预处理输入。
- 单次识别只展示文本与规则命中预览，不进入发送队列；运行中复用最近结果或待当前任务结束后执行，不并行抢占。
- 单帧失败记录错误并继续；连续 3 次失败暂停关键词分支，显示“重试 OCR”。空文本是有效结果，不是错误。

### F04 关键词管理与匹配

关键词页使用表格和独立编辑面板：列表仅包含启用、关键词、次数阈值、发送策略摘要和编辑入口；摘要显示“继承默认”或“自定义”。编辑面板按“匹配条件、发送条件、消息格式、发送对象”分组，长消息在详情中编辑。支持新增、编辑、删除、批量启停、搜索；删除提供撤销入口。

| 字段 | 规则 |
| --- | --- |
| `id` | 稳定 UUID，编辑不更换 |
| `keyword` | 必填，去除首尾空白后 1–100 字符；匹配时去除全部空白 |
| `min_count` | 1–999 整数，默认 1 |
| `custom_message` | 可空，最多 2000 字符；允许换行，按普通文本发送 |
| `enabled` | 默认开启 |
| `sort_order` | 确定同帧多规则的处理顺序 |
| `send_overrides` | 可空；条件、格式、对象各自独立选择继承默认或覆盖，详见 F07.1–F07.3 |

匹配规则：OCR 文本和关键词均去除 Unicode 空白，保留大小写和标点，按字面值做非重叠子串计数。阈值指单次 OCR 结果内的次数，不跨帧累计。例如 `Cerb` 阈值 5，4 次不触发、5 次触发；`aaaa` 中 `aa` 为 2 次；`Cerb` 不匹配 `cerb`。归一化后相同的关键词不可重复新增。

默认冷却 60 秒，可设 0–86400 秒，规则可单独覆盖；按“账号 + 目标类型/ID + 规则 ID”独立计时。任务接纳即占用规则，同一规则在待发送或执行期间不能再次入队，即使冷却为 0 也不能重复占用。默认持续命中允许冷却结束后再发一次，也可选择“每轮命中仅发一次”，详见 F07.1。

规则修改以完整事务保存，纯匹配字段修改从下一帧应用；发送策略和对象变更按 F07.3 暂停关键词分支后应用。删除、禁用、修改规则时取消该规则尚未发送的任务；已发出的网络请求不可撤回。编辑不能清除既有冷却。更换账号、采集源或 ROI 需暂停全部监控并清空未发送任务。

### F05 导入、导出及持久化

- 保留 `关键词|出现次数|消息` TXT 格式，支持 UTF-8、UTF-8 BOM 与 CRLF/LF；也允许仅含关键词的行，阈值默认 1，消息为空。
- 按前两个 `|` 切分，剩余内容完整作为消息，修复旧版多分隔符被截断的问题。空行忽略，非整数/越界阈值、空关键词报具体行号，不静默修改。
- TXT 关键词不能含 `|` 或换行；消息可含 `|`，多行消息不能无损导出 TXT，此时提示使用 JSON。JSON 为带 schema_version 的完整规则导入导出格式。
- 导入先预览有效条目、重复项、无效行，再选择合并或替换。默认合并且保留已有同名规则；可选择覆盖。文件内重复默认保留首条并列出冲突；无效行存在时必须明确选择仅导入有效条目。替换前自动备份数据库。
- 验收必须能导入现有 `legacy/keywords.txt` 的 11 条规则，保持阈值与消息。首次仅提示发现旧文件，不自动导入或覆盖。
- 每次保存持久化到用户目录 SQLite，失败时保留编辑内容并明确显示“未保存”。原 `legacy/` 文件保持不变。
- TXT 导入的规则默认继承发送条件和对象，非空旧消息作为固定文本覆盖消息正文；不把其中的花括号解释成模板变量。TXT 无法携带新增策略，导出前提示缺失字段，完整往返使用 JSON。
- 规则 JSON 包含发送覆盖项及其引用的默认策略快照；导入预览展示默认值差异，不自动覆盖当前全局设置。选择保留当前默认值时明确提示最终行为可能变化；目标绑定重新核验，凭据与 NapCat 会话不导出。

### F06 NapCat 配置、启动与应用内登录

官方提供 Windows Shell 启动包；原生适配器使用经验证的发行包启动入口，不假定 NapCat 是可被 Python 直接导入的库。[官方启动说明](https://napneko.github.io/guide/boot/Shell)

- “QQ 连接”页分为“运行与登录”和“NapCat 配置”两个页签，提供选择目录、启动、停止、重启和日志入口；对象配置统一位于“发送配置”页，本页仅显示默认对象摘要和跳转入口。
- 默认受管理模式：应用使用独立运行目录，验证版本和完整性，生成本实例配置，隐藏控制台运行；记录 PID、启动时间、可执行路径及进程归属。
- 可选附加模式：连接用户已有本机 NapCat，用户输入管理地址和凭据。附加模式不修改安装目录，不启停外部进程；它不能替代首版受管理模式验收。
- 管理接口和 OneBot 通道分开检测与鉴权；二维码成功展示不代表消息通道已经可用。
- WebUI 管理端用于登录控制；原生页面通过 Python 适配器取得二维码与状态。官方当前源码提供登录状态、二维码刷新及快速登录处理器，但路由、认证算法、响应字段需针对冻结版本做契约测试，不能视作 OneBot 11 标准能力。[上游登录实现](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-webui-backend/src/api/QQLogin.ts)
- 二维码按整数倍缩放，白底、留足静区，不加圆角裁切。过期时覆盖状态层并提供刷新；登录成功立即清除二维码。接口未提供过期时间时不显示假倒计时。
- 原生登录状态：未安装、已停止、启动中、等待登录、待手机确认（可观测时）、已登录但消息通道未就绪、可发送、离线、错误。显示当前账号昵称和 QQ 号。
- 首版支持扫码与有效会话复用，不收集或存储 QQ 密码；遇到设备验证显示官方提供的操作信息，由用户在手机端处理，不绕过验证。
- 启动等待上限 60 秒，登录等待不设置虚构超时，使用真实二维码状态；用户可随时取消启动或关闭登录页，后台状态仍可恢复查看。
- 端口冲突显示占用问题并允许重新选择本实例端口。禁止静默连接一个账号未知的服务；连接成功后验证账号，切换账号后目标重新核对。
- WebUI 或登录接口不兼容时显示具体版本与修复入口，不以“打开外部浏览器即可”作为完成应用内登录的验收替代。

#### F06.1 NapCat 可视化配置

首版覆盖本应用运行所需的 NapCat 配置，不要求用户打开 NapCat WebUI 或手工编辑配置文件。发送条件和模板由 Python 业务层执行，NapCat 承担登录、连接和消息传输；界面统一提供配置入口，避免用户理解内部模块划分后才能使用。

| 配置组 | 应用内配置项 | 默认交互 |
| --- | --- | --- |
| 运行环境 | 受管理/附加模式、安装目录、兼容版本、随应用启动 NapCat | 目录选择器，自动检测；随应用启动默认关闭 |
| 本机连接 | 管理端口、OneBot 正向 WS 端口、通道启用状态 | “自动配置本机连接”生成可用方案，端口冲突可一键重新选择 |
| 连接凭据 | 管理端与 OneBot 独立凭据 | 自动生成，默认掩码，可重新生成；不在摘要和日志暴露 |
| 高级连接 | 心跳间隔、连接检查、NapCat 日志级别 | 默认折叠，提供恢复默认与字段解释 |
| 应用通信策略 | 请求超时、断线重连开关与最大重连间隔 | 与运行时字段区分保存；使用已有默认值 |

受管理模式只监听本机回环地址，传输方式固定为本应用支持的正向 WS；管理端口和 WS 端口必须为 1024–65535 的不同整数。心跳间隔允许 5–60 秒、默认 30 秒，失活判定随之取两倍；请求超时 3–60 秒、默认 10 秒；最大重连间隔 5–60 秒、默认 15 秒，退避序列按该上限截断。修改前后均在页面显示实际状态，不提供不受支持的自由协议选项。

“保存草稿”“应用配置”“检测连接”职责明确：保存不影响当前运行；检测不发送 QQ 消息；应用前校验字段、备份旧值并展示是否需要重启。运行中需要重启时按钮明确标为“停止监控并应用重启”，取消则维持旧配置。应用过程暂停通知、取消未提交任务，写入兼容配置、必要时重启并重新鉴权；只有回读配置与连接验证通过，才标为“已生效”。完成后由用户重新开始监控。

界面分别显示草稿值与已生效值。写入、重启或验证失败时恢复上一份可用配置，并保留失败草稿供修改；回滚失败显示“连接未恢复”，不错误展示在线。发现外部配置变更时先展示差异，不静默覆盖。所有适配路由和生效方式在 M0 针对冻结版本验证；不预设每个字段都能热更新。

附加模式在应用内配置本应用连接所需的地址、凭据和通信策略，并检测已有服务；不修改外部实例的服务器配置、不触发其重启。需要完整管理时提供“导入为独立受管理实例”入口，重新配置和登录，不复制外部实例的会话或覆盖其目录。

### F07 目标选择与发送

NapCat 提供好友/群列表、登录信息与消息发送 API；本产品只调用实现通知所需的能力。[官方 API 列表](https://napneko.github.io/onebot/api)

- 按好友、群分组，支持名称与 ID 搜索、刷新；选择项同时显示类型、名称和完整 ID。显示名不能作为路由依据。
- 保存账号绑定的目标 ID。列表刷新失败时保留已有展示但标记未验证；账号变化或目标失效时禁止自动发往其他对象。
- 发送正文与目标根据 F07.1–F07.3 的默认值和规则覆盖解析；传统规则仍按“定制消息 > 首个命中行或全文”生成文字。跨行归一化命中但无单行命中时回退全文；超 2000 字符的自动正文截断并附标记，完整文本可在本地识别详情查看。
- 使用 OneBot 消息段数组，文字作为 text，图片作为 image；不把识别内容当作 CQ 指令解析。
- “文字 + 截图”模式先发送文字，取得成功回执后发送同一次命中帧的原始 ROI PNG。图片失败标记“部分成功”，不得重发已成功文字；“仅截图”模式直接发送该 PNG，不生成空文字请求。
- 默认倒计时 3 秒，可选 0/3/5 秒。非模态待发送条目显示关键词、账号、目标、正文摘要、截图标识、剩余时间和取消按钮。
- 默认全局每 2 秒最多发起 1 个消息 API 请求；同帧不同规则按排序入队；待处理上限 100 个任务，帧引用共享，内存图片总量上限 64MiB，超限拒绝新任务并记日志。
- 倒计时从任务进入队首开始；任务从生成起 60 秒过期，开始倒计时和实际发送前都检查有效期、会话版本及停止标志。重连后不补发离线期间的历史命中。
- 每个 API 请求超时默认 10 秒，可在高级连接设置中调整；收到明确成功回执记录 message_id。成功只表示接口接受成功，不表示接收方已读。
- 明确拒绝为失败；断连或超时且请求可能已提交时为“结果未知”。首版不自动重试发送请求，避免重复通知；允许用户查看记录后显式重试失败部分，未知结果重试必须提示可能重复。
- QQ 断线时取消尚未提交的任务，关键词识别可继续显示结果，标记“通知暂停”；色块不受影响。重新连接并验证相同账号和目标后仅处理新命中。
- 停止监控立即取消未提交的文字/截图与倒计时。已经提交的请求继续收集回执并标记“停止前已提交”，无法保证撤销。

#### F07.1 发送条件

“发送配置 → 发送条件”设置默认值，关键词编辑面板可逐项覆盖。次数阈值仍在规则中设置；下面的条件按 AND 组合，界面自动生成说明，例如“Cerb 单帧出现至少 5 次，连续 2 帧满足，每轮命中发一次，冷却 60 秒”。

| 条件 | 选项与语义 |
| --- | --- |
| 规则启停 | 关闭后不发送，不影响其他规则 |
| 单帧次数 | 沿用 min_count；不能把多帧次数累加到阈值 |
| 连续确认 | 1–10 帧，默认 1；连续有效 OCR 帧达到阈值才满足；低于阈值、识别失败或会话变化清零 |
| 重复方式 | 默认“持续命中按冷却重复”；可选“每轮命中仅发一次”，须有一帧有效结果低于阈值后才能重新触发；失败帧不解除这一占用 |
| 冷却 | 默认 60 秒，0–86400 秒；可单独覆盖，任务接纳后计时 |
| 发送前倒计时 | 默认 3 秒，0/3/5 秒；可取消，规则可覆盖 |

共同前置条件包括账号在线、目标有效、格式有效、队列可接纳。仅当任务实际被队列接纳才消耗一轮触发机会；被取消、发送失败或结果未知时保留该轮占用和已有冷却，不自动重试。“每轮命中仅发一次”在编辑/暂停/断连后对同一规则和目标保留占用，直到有效未命中帧；重启程序建立新轮次且默认不自动监控。

连续确认只使用自动监控的不同帧 ID；手动识别、本地试算不推进计数、不改变冷却。色块报警继续使用独立条件，首版不新增色块触发 QQ 通知。

#### F07.2 发送格式与预览

- 消息类型提供“仅文字”“文字 + 区域截图”“仅区域截图”，默认仅文字。选择截图模式后显示取图范围说明与缩略图。
- 文字来源提供“首个命中行”“完整识别文本”“固定文本”“消息模板”，默认首个命中行。固定文本按原样发送；选择模板后才展开变量插入按钮。
- 模板支持 `{keyword}`、`{count}`、`{threshold}`、`{hit_line}`、`{ocr_text}`、`{capture_time}`。时间使用命中帧采集时的本地时间 `YYYY-MM-DD HH:mm:ss`；模板不执行 Python 表达式、脚本或任意格式化代码，双花括号表示字面花括号。
- 内置“简洁提醒”“关键词 + 命中行”“时间 + 完整文本”预设，可直接选用再修改。例如：`【屏幕提醒】{keyword} 出现 {count} 次（阈值 {threshold}）\n{hit_line}`，编辑器中的换行实际按多行文本存储。
- 每条规则可以覆盖消息类型和正文配置；旧 `custom_message` 非空时映射为该规则的固定文本正文。用户选择新的正文来源时同步替换这一映射，避免两个正文配置同时生效。
- 编辑时显示实时预览、最终字符数、图片位置和实际对象。未知变量、缺少固定文本/模板、模板语法错误不能保存为有效配置；模板长度最多 2000 字符，渲染后超限沿用截断策略并在预览标明。
- 预览与真实发送共用渲染逻辑，变量缺少真实值时使用明确标注的示例值。实际任务取同一帧的数据快照；仅截图模式无需验证未启用的正文配置。

#### F07.3 发送对象与配置生效

- 默认对象在“发送配置 → 发送对象”选择，可按好友/群切换、名称或 ID 搜索；展示近期选择、刷新按钮与账号信息。近期列表不代替在线有效性核验。
- 每条规则选择“继承默认对象”或“指定好友/群”。指定对象显示名称、类型和 ID；默认对象变更只影响继承规则，页面展示受影响规则数量。
- 默认策略和规则覆盖采用逐字段继承，不复制默认值作为覆盖；切回“继承默认”立即预览当前默认值。最终摘要必须同时展示条件、格式、账号与对象。
- 无默认对象时，已指定有效对象的规则可正常使用；任何启用规则的最终对象未配置或格式无效时，阻止启动关键词监控并列出具体规则。运行中单个目标失效只暂停受影响规则；切换 QQ 账号要求重新核验所有绑定，不自动迁移目标。
- 点击“应用发送配置”原子保存本应用策略，暂停关键词分支并取消受影响规则的未提交任务，重新验证后由用户继续；色块分支保持运行。纯业务策略变更无需重启 NapCat；不可修改已提交请求的目标、正文或图片。

#### F07.4 配置试算与测试发送

页面提供规则选择、示例/最近识别数据切换和“一次试算”。试算逐项展示次数阈值、连续确认、冷却、通道与对象状态，指出“为什么会发/为什么不会发”；连续确认可显示当前计数与模拟下一帧结果，但不改变实际状态。

“预览/检测连接/保存”均不发消息。“测试发送到所示对象”显式发送当前预览快照，按钮旁显示账号、目标类型、名称和 ID，并给消息添加测试标识。测试不要求真实关键词命中、不改变生产冷却或轮次，但仍检查在线状态、格式、目标及限速；测试截图必须使用实际捕获帧。只测试当前选定规则的一个对象，不一次测试所有规则；记录中标注为测试。

### F08 色块闪烁报警

- 默认关闭；和关键词共用当前 ROI，独立采样 250ms，不依赖 OCR 完成或消息发送。
- 颜色分类基线保持旧版：最大 RGB 分量小于 60 忽略；RGB 均大于 205 且饱和度小于 0.3 判白；其余饱和度小于 0.25 忽略；HSV 色相小于 18°或大于等于 342°判红，剩余小于 55°判橙。
- 分类后按像素数量取主色，无有效颜色记“无”；数量相同按红、橙、白优先。轻量分析图缩为 ROI 的 1/4 尺寸并隔像素采样，最低 4×4。
- 相邻有效采样颜色不同，连续变化数 +1；相同归零。红→白→红→白→红为 4 次变化，触发报警。“无”参与状态变化；缺帧不等于“无”，缺帧或采样间隔超过 500ms 时重置连续性。
- 默认声音持续 3 秒、冷却 30 秒，冷却可设 0–86400 秒；持续闪烁可冷却后重复报警。相同声音不叠加播放；颜色稳定清零但已开始的 3 秒声音播完，停止监控/关闭模块则立即停止声音。
- 提供急促警报、双短鸣、长鸣、柔和提示、静音和试听。声卡不可用时仍显示报警状态及日志。
- 独立视图显示主色、连续变化数、最后报警时间；详细采样日志默认关闭。颜色名称用文字表示，主界面保持既定配色。

### F09 日志与诊断

分类：采集、OCR、关键词、发送、色块、NapCat、系统。支持级别/分类过滤、搜索、暂停滚动、复制单条、导出脱敏日志与清空视图；清空视图不等于删除磁盘文件。

默认写事件元数据、错误码、耗时、任务 ID 和回执；OCR 全文只在内存最近结果显示，诊断模式显式开启后才写入磁盘。Token、二维码、Cookie 和会话不得进入日志。磁盘日志每个 5MiB、最多 5 个文件；发送记录默认保留 7 天，保存摘要与状态，默认不落完整正文/图片。

### 6.3 动画

使用 PySide6 的 QPropertyAnimation/QVariantAnimation 和 QEasingCurve 完成属性过渡。[Qt 动画文档](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QPropertyAnimation.html)、[缓动示例](https://doc.qt.io/qtforpython-6/examples/example_widgets_animation_easing.html)

| 交互 | 时长 | 缓动与表现 |
| --- | --- | --- |
| 按钮 hover/press | 120/80ms | OutCubic，底色和边框渐变 |
| 页面切换 | 180ms | OutCubic，淡入、最多 8 DIP 位移 |
| 抽屉展开/收起 | 220ms | InOutCubic，平移与透明度 |
| 状态提示出现/消失 | 160ms | OutCubic 淡入，InCubic 淡出 |
| 开关滑块 | 140ms | OutCubic |

无弹跳、无持续呼吸灯、无全屏闪烁。快速重复交互从当前值续接动画，不累积动画队列。倒计时按真实时钟计算，动画不影响发送时间。提供“减少动画”设置，关闭位移和渐变后功能完整；系统减少动画设置可读时默认跟随。

## 7. 状态与一致性

监控状态：停止 → 准备中 → 运行；运行可转暂停或错误，再经用户重试恢复。QQ、OCR、采集各自有独立状态，不用一个“服务正常”掩盖局部失败。

启动条件：采集源有效，至少开启一个模块；关键词模式还要求至少一条启用规则、OCR 就绪、QQ 可发送，且每条启用规则的最终格式和目标有效；色块模式不检查这些条件。所有禁用按钮旁提供具体原因。

锁屏/休眠立即暂停采集和自动发送并取消待发任务；解锁/唤醒后展示恢复入口，用户点击继续后重新验证源与 QQ。主窗口失焦或最小化不触发这种暂停。

队列状态：待发送 → 倒计时 → 发送中 → 成功/部分成功/失败/结果未知；待发送、倒计时可转取消/过期。每个任务携带 session_id、配置修订号、规则 ID、帧 ID、目标快照；旧会话迟到结果不可进入新会话。

## 9. 数据与本地安全边界

配置、数据库、日志、运行时与缓存统一放到 `%LOCALAPPDATA%\ScreenQQOCR\`，不写入安装目录，不要求管理员权限运行核心程序。数据库使用 schema_version 与事务迁移，升级前备份；迁移失败保持旧库，进入可诊断状态。

本应用持有的管理凭据保存在 Windows Credential Manager 或等效用户级保护存储；NapCat 自身要求落盘的配置 Token 位于隔离目录，以当前用户 ACL 保护，不能声称第三方运行时全部加密存储。WebUI 与 OneBot 默认只绑定 `127.0.0.1`，均启用独立凭据；日志和配置导出必须脱敏。

下载/导入运行时检查发行来源、清单版本、SHA-256 与路径；解压拒绝目录穿越，不覆盖用户独立 QQ 安装。首版维护经实测的 NapCat/QQ 组合，升级只在停止监控后由用户主动执行，并保留旧版本恢复入口。
