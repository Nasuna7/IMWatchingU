## 改动

- 显示器存在性仅比较位置和尺寸；兼容 mss 的 is_primary、name、unique_id 等附加字段，主显示器标识显示在来源列表。
- WGC 静态画面不再因两秒未更新而报错；首次等待扩展到约六秒。关闭/最小化校验仍保留。保留原始帧 ID，缓存画面不会被当作新的连续确认帧。
- MonitorTasks 管理独立 Monitoring 实例；每个实例拥有串行采集线程、Capture、OcrWorker、ROI 和 TriggerTracker。每次实际 OCR 在独立子进程执行，关闭时回收。
- 各任务共用规则库、QQ 连接和串行发送队列。SendTask 增加 monitor_id，冷却按任务隔离，取消一个任务只影响该任务，发送限速和容量预算仍全局共享。锁屏、退出及“停止全部”覆盖全部任务。
- Preview 始终显示完整来源；选区以来源归一化坐标保存，可新建、移动、八方向缩放、边界限制和重置。应用层验证最小 16×16 像素后提交；运行中修改区域使旧 OCR 结果失效并恢复监控。
- 关键词表格增加直接可编辑的数量控件，编辑区文案明确“目标数量（单帧至少）”，保存到原 min_count 字段，保持导入导出兼容。
- NapCat Shell 支持本机启动文件、配置目录和账号配置选择、已有 token 读取、缺失配置生成、备份与本机管理端等待。已占用管理端口先附加鉴权，不重复启动或覆盖运行中配置；没有真实 QQ 自动发送测试。

## 使用与剩余边界

修正版构建目录为 `dist/fixes/ScreenQQOCR/`，保留正在运行的旧版目录。先从旧版托盘退出，再打开新版；用户数据目录与数据库保持兼容。

监控任务仅在本次运行中保留，重启后重新选择来源和区域。当前任务共享关键词与发送策略；不同任务可以使用不同来源和 ROI，尚无逐任务规则集合。WGC 对同名标题歧义、最小化窗口及受保护内容仍有约束。

NapCat 需要已安装的本机 Shell，配置文件目前读取标准 JSON。选择的 config 目录必须确实被 Shell 使用；多个账号需选择正确账号配置。已有监听端口不能证明是所选 NapCat，仍以鉴权和账号核验为准。退出应用保留 NapCat，不提供外部进程终止。真实 QQ 扫码、账号配置匹配、收发及各种发行版启动脚本兼容性尚未进行端到端验收；自动下载安装、升级、启动失败后的完整事务回滚与崩溃恢复不在本次已实现范围。
