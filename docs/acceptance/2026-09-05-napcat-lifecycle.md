# NapCat 退出回收修复

原实现仅断开 OneBot/管理连接，隐藏启动的 NapCat 及 QQ 子进程仍保持登录。本次恢复 PRD 的所有权边界：本应用启动的进程树随应用退出；附加外部实例只断开连接。

- Windows Job Object 管理整组进程，挂起启动并先绑定 Job，避免子进程抢先脱离管理；启动脚本先退出也可回收。
- 启动/停止通过锁串行化；退出标记阻止后台线程迟到启动。连接清理失败也执行 NapCat 回收。
- 新增“停止本应用启动的 NapCat / 释放账号”按钮；明确“断开消息连接”不会退出 QQ 登录，托盘隐藏仍继续运行。
- 本机管理接口确认遗留实例登录昵称为“机器GG”，已关闭对应后台进程；6099/3001 监听释放，另一个普通 QQ 实例仍运行。未发送消息，未删除登录数据。

验证：完整自动测试 71 项通过，Ruff 检查通过。新增真实 Windows 子进程测试覆盖启动器先退出后回收、关闭 Job 句柄回收、绑定 Job 失败时回收挂起进程；其他测试覆盖启动/退出并发、重复停止、关闭后拒绝启动及消息断开异常时仍回收。

开发版和打包版独立数据目录 smoke test 均以 0 退出；额外在真实 GUI 退出流程中注入合成启动器，验证启动器提前退出后，其后台子进程仍被应用退出流程回收。该检查不启动真实 QQ。PyInstaller 构建成功。

构建输出：`dist/lifecycle/ScreenQQOCR/ScreenQQOCR.exe`。已有外部实例不会因升级自动纳入进程管理；请从新版的启动按钮启动 NapCat，后续退出即可自动回收。此修复不清除持久化登录凭据，下次启动仍可能恢复登录。
